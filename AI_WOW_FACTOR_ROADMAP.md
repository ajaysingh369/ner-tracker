# RunAstra Advanced AI Roadmap: The "Wow" Factor

This document outlines the strategic implementation plan for three cutting-edge, on-device AI features designed to elevate RunAstra from a standard fitness tracker to a world-class, intelligent running companion.

---

## Feature 1: Acoustic Stride Guard & Shoe Degradation Monitor
**Concept:** Utilize the smartphone microphone to analyze the acoustic signature of footfalls. Detects form breakdown due to fatigue (heavier landings) and shoe cushioning degradation over time.

### Technical & Resource Impact
*   **App Size Increase:** ~2 MB (Fast Fourier Transform logic + Tiny 1D CNN model for acoustic peak classification).
*   **Cost Increase:** $0 (100% On-Device Inference).
*   **Battery Usage:** Medium. Continuous audio sampling can drain battery. 
    *   *Mitigation:* Only activate the microphone sampling in 15-second bursts every 1 kilometer, triggered by the pedometer/GPS.
*   **Development Complexity:** High. Requires signal processing (DSP) to isolate footfall sounds from background street noise/music.

### Development Plan
1.  **Data Collection Phase:** Build a hidden developer toggle to record audio during our own runs to build a training dataset of "fresh" vs. "fatigued" steps.
2.  **Model Training:** Train a lightweight TensorFlow Lite Audio Classification model on the isolated step peaks.
3.  **App Integration:** Use `react-native-audio-record` to capture raw PCM data, run FFT in a background worklet (using Reanimated or native bridge), and pass to the TFLite model.

## Feature 2: Zenith Voice Scan (Vocal Biomarkers)
**Concept:** A 15-second vocal check-in before a run. AI analyzes micro-tremors and pitch to assess respiratory readiness, CNS (Central Nervous System) fatigue, and recovery status, dynamically adjusting the Zenith target.

### Technical & Resource Impact
*   **App Size Increase:** ~15 MB (if using local TFLite Speech-to-Text/Emotion model) OR ~1 MB (if using Cloud API).
*   **Cost Increase:** 
    *   *Cloud Route (Sonde Health / Bedrock Audio):* Low to Medium ($0.001 per scan).
    *   *Local Route:* $0.
*   **Battery Usage:** Negligible. It only runs for 15 seconds while the user is actively looking at the screen before a run.
*   **Development Complexity:** Medium.

### Development Plan
1.  **UX Design:** Create a beautiful, glowing "Push to Talk" orb on the pre-run screen.
2.  **Implementation (V1 - Cloud):** Send a compressed audio snippet to a backend Lambda. Use AWS Transcribe + Bedrock to analyze the sentiment/breathiness and return a "Readiness Score."
3.  **Implementation (V2 - Local):** Integrate a specialized audio TFLite model (e.g., YAMNet) to extract acoustic features locally.

## Feature 3: AI Form Coach (Markerless Gait Analysis)
**Concept:** User records a 5-second video of themselves running past the camera. The app uses pose estimation to provide a pro-grade biomechanical report (Foot Strike angle, Knee Flexion, Overstriding).

### Technical & Resource Impact
*   **App Size Increase:** ~25 MB (MediaPipe BlazePose model binaries).
*   **Cost Increase:** $0 (100% On-Device Computer Vision).
*   **Battery Usage:** High (during use). Running 30FPS computer vision maxes out the GPU/NPU.
    *   *Mitigation:* Only used actively for 5-10 seconds while the user is analyzing a video. Not a background task.
*   **Development Complexity:** Very High. Requires native bridging of Google MediaPipe or wrapping an SDK like QuickPose.ai. Mathematical calculation of joint angles required.

### Development Plan
1.  **PoC (Proof of Concept):** Implement `react-native-vision-camera` to capture high-framerate video.
2.  **Pose Extraction:** Integrate the BlazePose TFLite model using `react-native-fast-tflite` to extract the 33 3D body landmarks frame-by-frame.
3.  **Biomechanics Engine:** Write a TypeScript engine that calculates the Initial Contact (IC) frame and measures the tibial angle to determine heel vs. midfoot strike.
4.  **Reporting UI:** Build a highly visual "Lab Report" screen overlaying the skeleton on the user's video, with actionable insights generated by Astra (via Bedrock).

## Strategic Optimization: On-Demand Model Downloading (OTA)
**Problem:** Bundling 15MB to 25MB `.tflite` models directly into the app significantly increases the initial download size on the Play Store, which can reduce install conversion rates.
**Solution:** Over-The-Air (OTA) runtime downloading.

1.  **Cloud Hosting:** We host the heavy `.tflite` model files on our existing AWS CloudFront CDN (`d55rfskkr27b0.cloudfront.net`).
2.  **Runtime Fetch:** When a user taps the "AI Form Coach" or "Voice Scan" for the very first time, the app uses `expo-file-system` to download the model to the device's local storage.
3.  **UX:** The user sees a sleek loading bar ("Downloading AI Coach Neural Engine... 45%").
4.  **Local Inference:** Once downloaded, `react-native-fast-tflite` loads the model directly from the local file path (`file://...`). It never needs to be downloaded again.

**Result:** Initial app size remains tiny (<20MB), but the app can dynamically "unlock" massive AI capabilities at runtime.

## Cross-Platform & Hardware Compatibility
**Requirement:** All features must work on Android 8 (API 26) through Android 16, as well as iOS 13+.

1.  **Cloud AI (Bedrock):** 100% Cross-Platform. Since the processing happens on AWS via REST API, it relies entirely on the device's internet connection. It works flawlessly on any OS.
2.  **On-Device AI (TFLite via `react-native-fast-tflite`):**
    *   **Android:** The C++ bindings for TensorFlow Lite support Android API 16+. Our minimum requirement of API 26 (Android 8) is fully supported.
    *   **iOS:** Supported natively on iOS 9.0+ via CoreML delegates.
    *   **Hardware Caveat (The "Old Phone" Factor):** Modern phones (Android 12+ / iPhone 12+) have dedicated Neural Processing Units (NPUs) that run these models in ~10 milliseconds. An older Android 8 phone from 2017 lacks an NPU and will run the model on its CPU. This might take ~150 milliseconds.
    *   **Mitigation:** The AI logic runs asynchronously using Reanimated Worklets/JSI. This ensures the main UI thread never freezes, even on a slow 2017 Android device.
3.  **Sensors & Camera (MediaPipe / Accelerometer):**
    *   `expo-sensors` (Accelerometer/Mic) and `react-native-vision-camera` (Gait Analysis) support both iOS and Android (API 21+).
    *   **Background Restrictions:** Both iOS and modern Android (12+) severely restrict background sensor usage. Features like "Acoustic Stride Guard" will require explicit Foreground Service permissions (Android) or Background Audio capabilities (iOS) if they run while the screen is off.

**Conclusion:** The architectural strategy is fully sound across all requested platforms. We must ensure graceful degradation (asynchronous processing) for older hardware.

## Summary & Priority Recommendation
To achieve the highest "Wow" factor with the lowest immediate risk to app stability:

1.  **Priority 1: Zenith Voice Scan (Vocal Biomarkers).** It is interactive, feels like magic, has zero background battery drain, and perfectly integrates with our existing Astra AI Mascot persona.
2.  **Priority 2: AI Form Coach.** A massive USP for serious runners, highly shareable on social media, and zero background battery impact.
3.  **Priority 3: Acoustic Stride Guard.** The most difficult to engineer reliably due to real-world noise, but the ultimate holy grail for passive injury prevention.
